## A — Native Physics activation fixed

Rust `PhysicsConstraint.bone` becomes the author/export `target`, with empty
`bones`. It is the simulated bone, not a separate control bone. The TypeScript
evaluator only read bones[0]; an actual native export created zero simulation
states. The regression expected one and was red before correction.

The shared resolver now accepts native target-only, historical empty-target with
one bone, and redundant matching target/bone forms. Missing/unknown/conflicting
or multi-bone references fail explicitly, in parsing and direct stateful
evaluation. It neither mutates input nor guesses a bone. Valid v1/v2 reading,
existing fields and integrator behavior remain unchanged; no format bump.

Preflight changes diagnostic code `runtime-physics-incompatible` to
`runtime-physics-unqualified`. Consumers filtering codes must update their filter.
Consent stays mandatory; the message warns about pre-T839 consumers, simulation
differences, PixiJS refusal and unqualified Phaser physics. Rendered physics remains
blocked. Phaser's obsolete “not activated” warning is corrected only.

New Rust tests generate authentic native exports and controlled replay references,
and a pose-only draw-order mixing probe. Six TS tests cover activation, legacy
reading, malformed references, opt-in/zero-dt/mix-zero, deterministic resets and
existing transport behavior. Three small native fixtures are exact generated bytes.
The Pixi rejection test now supplies a valid Physics reference to reach the same
adapter capability refusal; its assertion and gate are unchanged. Its previous
`{type:'physics'}` stub is now rejected earlier by the core parser. No thresholds
or historical pixel oracles were changed. A separate fixture-portability commit
`ceb89438cb97b8e6f4790e2ab51a64a96f02bed4` marks only the new Physics fixtures
as binary (-text), matching existing oracle policy. A real Git checkout-filter
probe was red (1849→1889 bytes with CRLF), then green (1849 bytes unchanged).

## B — Physics synchronization audit, no solver change

| Aspect | Rust | TypeScript | Consequence |
|---|---|---|---|
| step | f32 1/120 | double 1/120 | numeric boundaries differ |
| cap | 8 | 32 | hitch response differs; both carry backlog |
| remainder | shared PhysicsState, consumed on each constraint advance | per constraint/bone | multi-constraint coupling differs |
| dt=0 | returns stored offsets without consuming backlog | may drain backlog | different behavior after a hitch |
| force | inverse-parent wind/gravity, mass>=.01, decay rate12 | same general equations | bounded common cases agree |
| parent motion | inverse-parent displacement, impulse divided by steps | same general equations | first anchor/caller cadence matters |
| mix | clamp after advancing | skip <=0; translation raw mix | off/on and out-of-range policy differs |

## D — Mixing audit, no mixing change

| Data | Existing semantics and reuse limits |
|---|---|
| translation/shear/rotation | weighted offsets accumulate from setup; angular samples use shortest arc; no normalized layer contract |
| scale | multiply each layer by 1+(sample−1)×alpha, not an arithmetic average |
| light RGBA | sequential lerp from current value; order matters |
| dark tint | static only; no invented animated channel |
| FFD | first sample×alpha, later sequential lerp; valid topology required; Rust keeps tail while TS can extend mismatched arrays (unqualified/malformed case) |
| attachments/visibility | highest alpha, later layer wins ties; before first key retains setup |
| draw order | Rust applies each winning key to current order; TS to setup; divergence below |
| events | stable chronological (from,to], t=0 excluded each lap; player emits incoming clip only |
| interrupted fade | outgoing snapshots current track, not last composite; visible discontinuity remains |
| future layers/sliders | existing evaluators reusable; no mask/layer authoring/parameter abstraction supplied |

New real native pose-only fixture: setup `[a,b,c]`, first clip moves a +2 at alpha
.4, second moves c −2 at alpha .6. Rust produces `[c,b,a]`; TypeScript `[c,a,b]`.
This is a P1 portability divergence when both clips animate order.
`export/tests/t839_mixing.rs` records native behavior and emits the actual export
and result to a new T839_MIXING_DIR. Delivery contains the TS comparison.
This is pose evidence, not graphical certification. Neither evaluator changed.
